# 결정 기록 (사이즈 어때?)

원본 기획: `docs/SUPER_PROMPT.md`(사이즈노트). 디자인 기준: `docs/design/reference-1.webp`, `reference-2.webp`(사용자 제공 시안).
API 근거: 설치된 `node_modules/@apps-in-toss/web-framework/dist/index.d.ts`(3.10.0)와 이전 프로젝트(내 차 어딨지·점심합의) 확인 결과.

| D-005 | 측정 출처를 측정 항목 단위(`source`)가 아니라 **치수 값 단위**(`MeasuredValue{ mm, origin, photo? }`)로 저장 | 사진 보조 측정은 길이 1개씩 나온다 → 가로는 직접 측정, 높이는 사진 참고값처럼 섞임. 기획 §18.1 "치수별 출처를 각각 표시"를 데이터로 보장 |
| D-006 | 사진 위 좌표는 **0~1 정규화 좌표**로 저장(+계산에 쓴 사진 픽셀 크기) | 화면 크기·확대·저장용 축소와 무관하게 다시 그리고 재계산 가능. 기획 §8.5 "원본 픽셀 ↔ 화면 좌표 변환"을 저장 단계에서 단순화 |
| D-007 | 시안의 탭바(홈·비교·설정)를 **사용**. 토스 내비게이션 바(뒤로·홈)는 그대로 두고 화면 안 뒤로가기는 브라우저 미리보기에서만 | 기획은 "자체 탭바 지양"이지만 시안 2종 모두 탭바. 내 차 어딨지 D-003과 같은 판단(앱 내부 화면 전환용) |
| D-008 | 시안 문구 **"설치 가능해요!" → "입력값 기준 규격 충족"**, "설치 가능" 배지 → 같은 문구 | 기획 §3.3·§5.4: 설치 가능을 보증하는 표현 금지 |
| D-009 | 화면 기본 단위 cm(시안 1), 설정에서 mm(시안 2) 전환. 저장은 항상 정수 mm | 두 시안이 단위가 다름. 변환은 `domain/units.ts` 한 곳 |
| D-010 | 판정: 축별로 `제품 + 확인된 설치 여유 ≤ 공간`. 가로=좌+우, 깊이=후면, 높이=상단 | 기획 §5.3. 전면 여유는 '문 개방 공간'(D-012)로 따로 다룸 |
| D-011 | 설치 여유 `null`=확인 안 함 → REVIEW, `0`=필요 없음을 사용자가 확인. 단, **확인된 값만으로 이미 넘치면 OVER** | 기획 §5.3·§5.4(초과가 확정되면 OVER 우선, 미확인은 별도 목록) |
| D-012 | 제품 `doorOpenMm`(문·서랍 개방 필요 거리) ↔ 측정 항목 `frontSpace`(앞쪽 빈 거리)를 별도 축으로 비교. 0이면 생략 | 시안의 "문 개방 공간은 추가 확인"을 계산 가능한 형태로. 모르면 REVIEW |
| D-013 | 사진 참고값·출처 미확인·측정일 없음·1년 넘은 측정은 판정을 바꾸지 않고 **주의(caution)** 로 표시 | 값이 같으면 판정도 같아야 일관적. 대신 결과 화면에 재측정 권고를 반드시 노출 |
| D-014 | 반입 경로 결과는 `SIMPLE_PASS` / `REVIEW` 두 가지. 폭이 모자라도 "불가"라고 하지 않음. 꺾임 모름·계단은 항상 REVIEW | 기획 §2.1-F·§5.5. 기울이면 들어갈 수 있으므로 단정 금지 |
